# LUMOS 0.8.1 검증 결과

## 검증 환경과 구분

로컬 Node.js 검사, Apps Script 서비스 모의 환경, Chromium 화면 점검을 수행했습니다. 실제 운영자의 Google Apps Script 배포·Google Sheets에서 가입이나 저장을 실행한 결과는 아닙니다. 사용자 배포 URL·시트 접근 권한을 제공받지 않았으며, 배포 설정 endpoint는 비워 두었습니다.

## 자동 검사

기존 게임 검사 223개와 새 계정·저장 검사 12개를 실행했습니다. 전체 235개 검사가 통과했습니다. 자세한 시나리오는 tests/accounts081.test.mjs에 있습니다.

| 기존 복구키 전환 및 구키 차단, 저장 행/ID 보존 | 모의 환경 통과 |
| 초기 설정 재실행, 대소문자 중복 계정·정지 계정·헤더 이상 | 모의 환경 통과 |
| 내보낸 진행에 비밀번호/세션 없음, 서버 표에 원문 없음 | 검사 통과 |

PBKDF2는 반복 수를 테스트용으로 낮추지 않고 600,000회로 검증했습니다. Node 표준 crypto.pbkdf2Sync 결과와 생성된 Code.gs의 결과를 대조했습니다. TextEncoder, crypto, Node 모듈이 없는 VM에서 Code.gs를 평가하고 GAS의 Utilities 바이트 변환을 모의하여 실행했습니다. 동일 장비에서 라이브러리의 네이티브 Node 실행은 약 531ms였으며, 이 수치는 Google의 실제 처리 속도가 아닙니다.

ScriptLock은 모의 객체로 경쟁 상황을 재현했습니다. 실제 Google 동시 실행·할당량·시트 I/O의 원자성·성능을 부하 시험한 것은 아닙니다.

## 브라우저 화면 점검

- 시작 화면의 로그인·회원가입·비로그인 플레이 확인.
- 회원가입 조건 사전 표시, 비밀번호 표시/숨기기 전환 확인.
- 이전 복구키 전환 화면과 운영자 초기화 안내 확인.
- 비로그인 이동과 게임 시작, 설정의 저장 기능 확인.
- 실제 로그인 자격 증명을 브라우저에 입력하거나 Google에 시험 계정을 생성하지 않았습니다. 가입·로그인·비밀번호 변경의 데이터 흐름은 위 모의 검사 결과입니다.

## 운영자가 실제 Google 배포에서 확인할 항목 — 아직 미검증

1. setupRpgSheets 권한 승인, 기존 시트 보존 및 추가 열 생성.
2. 익명 웹 앱 접근 권한, ContentService 리디렉션/CORS, 실제 GitHub Pages에서 응답 JSON 읽기.
3. benchmarkPasswordHash 실제 처리 시간, 할당량, 동시 접속 시 응답 시간.
4. 별도 두 브라우저의 가입·로그인·저장·불러오기·로그아웃.
5. 기존 계정 전환 및 운영자 초기화 코드 대화창, Drive 백업 사본.
6. 실패 시 성공 표시가 나오지 않고 기기 진행이 남는지 확인.

위 점검 전에는 실제 Google 클라우드 저장 검증 완료로 간주하면 안 됩니다. 운영 규모가 Apps Script 한도를 넘으면 인증 서버 분리가 필요하며, 반복 수를 줄여 우회하지 않습니다.
